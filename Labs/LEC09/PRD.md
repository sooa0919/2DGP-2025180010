# Sonic Animation Viewer PRD

## 1. 문서 목적

`sonic-sprite.png`에 포함된 소닉의 애니메이션 동작을 순서대로 재생해 확인할 수 있는 데스크톱 뷰어를 개발한다. 이 문서는 기능, 품질 기준, 제약사항 및 단계별 개발·커밋 계획을 정의한다.

## 2. 제품 개요

- **제품명:** Sonic Animation Viewer
- **대상 사용자:** 스프라이트 시트에 포함된 소닉 애니메이션을 확인하려는 개발자 및 수업 참여자
- **개발 언어/라이브러리:** Python, pico2d
- **실행 파일:** `sonic_animation_viewer.py`
- **입력 이미지:** `sonic-sprite.png` (프로그램 파일과 같은 `Labs/LEC09` 폴더)
- **파일 제약:** 애플리케이션 코드는 단일 Python 파일로 작성한다.

## 3. 목표와 범위

### 목표

1. 스프라이트 시트에 들어 있는 모든 식별 가능한 동작을 재생한다.
2. 각 동작의 애니메이션을 5회 반복한 뒤 1초간 대기하고 다음 동작으로 넘어간다.
3. 마지막 동작까지 재생한 뒤 처음 동작으로 돌아가 전체 순서를 무한 반복한다.
4. 소닉 스프라이트를 화면에서 알아보기 쉽도록 충분히 확대해 표시한다.

### 범위 제외

- 스프라이트 시트 편집 또는 이미지 변환 도구
- 사용자 지정 동작 순서, 재생 횟수, 배율 설정 UI
- 일시정지, 프레임 단위 이동, 애니메이션 선택 UI
- 별도 설정 파일 또는 추가 애플리케이션 모듈

## 4. 사용자 흐름

1. 사용자가 `sonic_animation_viewer.py`를 실행한다.
2. 프로그램이 같은 폴더의 `sonic-sprite.png`를 불러오고 뷰어 창을 표시한다.
3. 첫 번째 동작부터 프레임 애니메이션을 자동 재생한다.
4. 각 동작을 5회 재생하고 1초간 대기한 다음 다음 동작을 재생한다.
5. 모든 동작을 재생한 뒤 같은 순서를 다시 시작한다.
6. 사용자가 창 닫기 이벤트를 보내면 프로그램이 정상 종료된다.

## 5. 기능 요구사항

| ID | 요구사항 | 완료 기준 |
|---|---|---|
| FR-01 | 시작 및 자산 로드 | 프로그램 실행 시 `sonic-sprite.png`를 불러와 뷰어 창을 표시한다. 이미지가 없거나 로드할 수 없으면 원인을 알 수 있는 오류를 출력하고 비정상적인 이미지 접근 없이 종료한다. |
| FR-02 | 동작 및 프레임 구성 | 스프라이트 시트의 프레임 경계와 동작 구성을 확인해 목록화하고, 식별 가능한 모든 동작을 재생 대상으로 포함한다. 프레임을 잘못 자르거나 다른 동작의 프레임을 섞지 않는다. |
| FR-03 | 프레임 애니메이션 | 현재 동작의 프레임을 정해진 순서로 시간에 따라 표시한다. 프레임 인덱스는 동작의 프레임 수를 넘지 않고 끝에서 처음으로 순환한다. |
| FR-04 | 화면 표시 | 스프라이트를 충분히 확대해 창 안에 표시하고, 원본 비율을 유지하며 화면 경계에서 잘리지 않게 한다. 배경과 캐릭터가 명확히 구분되어야 한다. |
| FR-05 | 동작 반복 | 각 동작의 프레임 애니메이션을 정확히 5회 재생한 후 다음 동작으로 이동한다. |
| FR-06 | 동작 간 대기 | 동작을 5회 재생한 뒤 다음 동작을 시작하기 전 1초간 대기한다. 마지막 동작 뒤에도 동일하게 대기한 다음 처음 동작으로 돌아간다. |
| FR-07 | 전체 순서 반복 | 스프라이트 시트에서 정한 동작 순서를 끝까지 재생한 다음, 첫 동작부터 같은 순서로 무한 반복한다. |
| FR-08 | 종료 처리 | 창 닫기 이벤트를 처리하고 pico2d 리소스와 프로그램을 정상적으로 종료한다. |

## 6. 비기능 요구사항 및 제약

- 애니메이션과 대기 시간은 프레임 카운트가 아니라 경과 시간을 기준으로 처리한다. 실행 환경의 프레임 속도 변화가 1초 대기 및 동작 반복 횟수를 바꾸지 않아야 한다.
- 확대 시 가로세로 비율을 유지하고, 스프라이트가 창을 벗어나 잘리지 않도록 한다.
- 애플리케이션 구현은 `sonic_animation_viewer.py` 한 파일에 둔다. 입력 스프라이트 시트는 제공된 별도 이미지 파일로 유지한다.
- 코드와 실행은 저장소에서 사용하는 Python 및 pico2d 환경을 전제로 한다.
- 정확한 프레임 경계, 동작별 프레임 수, 동작 순서는 이미지 자산을 기준으로 확인해 구현 단계에서 기록한다. 이 문서에서 추정값을 고정하지 않는다.

### 제공 스프라이트 자산 기록

- `sonic-sprite.png`는 399×525 픽셀의 PNG이며, 8비트 RGBA 색상과 알파 채널을 사용한다.
- 이미지에는 투명 배경이 포함되어 있어 뷰어 배경색 위에 스프라이트를 표시할 수 있다.

## 7. 검수 기준

1. `Labs/LEC09`에서 프로그램을 실행하면 제공된 이미지가 표시된다.
2. 스프라이트가 원본 비율을 유지하며 충분히 크게 보이고, 화면 밖으로 잘리지 않는다.
3. 확인된 모든 동작이 정해진 순서대로 재생된다.
4. 각 동작은 정확히 5회 재생되고, 다음 동작 전 대기 시간은 1초다.
5. 마지막 동작 다음에는 1초 대기 후 첫 동작부터 전체 순서가 다시 시작된다.
6. 창을 닫으면 프로그램이 정상 종료된다.
7. 이미지 파일이 없는 경우 오류가 명확하게 드러나며 traceback에 의존하는 불명확한 종료를 하지 않는다.

## 8. 단계별 개발 및 커밋 계획

각 단계가 동작 가능한 상태를 만들도록 작게 나누며, 단계 완료 시 해당 변경만 별도 커밋할 수 있다. 아래 24단계는 최소 단계 수(20단계)를 충족한다.

| 5 | 스프라이트 이미지 로드 및 로드 실패 처리를 추가한다. | `기능: 소닉 스프라이트 로드` |
| 6 | 이미지 크기와 투명 영역 등 자산 특성을 확인하고 기록한다. | `문서: 스프라이트 시트 특성 기록` |

| 8 | 확정된 동작별 프레임 범위를 코드 데이터로 표현한다. | `기능: 동작별 프레임 범위 정의` |
| 9 | 단일 프레임을 지정해 화면에 그리는 경로를 구현한다. | `기능: 스프라이트 프레임 그리기` |
| 10 | 화면 중앙 배치 및 원본 비율 유지 표시를 구현한다. | `기능: 스프라이트 중앙 배치` |
| 11 | 화면 크기에 맞는 확대 배율과 잘림 방지를 적용한다. | `기능: 스프라이트 확대 표시` |
| 12 | 캐릭터가 잘 보이도록 배경 표시를 정한다. | `기능: 스프라이트 배경 대비 개선` |
| 13 | 현재 동작 및 프레임 상태를 관리한다. | `기능: 애니메이션 재생 상태 관리` |

| 24 | 실행 방법과 알려진 자산 가정을 정리하고 최종 동작을 확인한다. | `문서: 소닉 애니메이션 뷰어 사용법 정리` |
