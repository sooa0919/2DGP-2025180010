# Sonic Animation Viewer PRD

## 1. 문서 목적

`sonic-sprite.png`에 포함된 소닉의 애니메이션 동작을 순서대로 재생해 확인할 수 있는 데스크톱 뷰어를 개발한다. 이 문서는 기능, 품질 기준, 제약사항 및 단계별 개발·커밋 계획을 정의한다.

## 2. 제품 개요

- **제품명:** Sonic Animation Viewer
- **대상 사용자:** 스프라이트 시트에 포함된 소닉 애니메이션을 확인하려는 개발자 및 수업 참여자
- **개발 언어/라이브러리:** Python, pico2d
- **실행 파일:** `sonic_animation_viewer.py`
- **입력 이미지:** `sonic-sprite.png` (프로그램 파일과 같은 `Labs/LEC09` 폴더)
- **파일 제약:** 애플리케이션 코드는 단일 Python 파일로 작성한다.

## 3. 목표와 범위

### 목표

1. 스프라이트 시트에 들어 있는 모든 식별 가능한 동작을 재생한다.
2. 각 동작의 애니메이션을 5회 반복한 뒤 1초간 대기하고 다음 동작으로 넘어간다.
3. 마지막 동작까지 재생한 뒤 처음 동작으로 돌아가 전체 순서를 무한 반복한다.
4. 소닉 스프라이트를 알아보기 쉽게 확대하고, 넓은 가로 캔버스에서 이동 공간을 제공한다.
5. 걷기와 달리기 동작 중 방향키를 누르고 있으면 캐릭터가 화면 안에서 연속 이동한다.
6. 지정된 달리기/구르기 동작은 다섯 번 재생되는 동안 왼쪽에서 오른쪽으로 자동 이동한다.

### 범위 제외

- 스프라이트 시트 편집 또는 이미지 변환 도구
- 사용자 지정 동작 순서, 재생 횟수, 배율 설정 UI
- 일시정지, 프레임 단위 이동, 애니메이션 선택 UI
- 별도 설정 파일 또는 추가 애플리케이션 모듈

## 4. 사용자 흐름

1. 사용자가 `sonic_animation_viewer.py`를 실행한다.
2. 프로그램이 같은 폴더의 `sonic-sprite.png`를 불러오고 뷰어 창을 표시한다.
3. 첫 번째 동작부터 프레임 애니메이션을 자동 재생한다.
4. 각 동작을 5회 재생하고 1초간 대기한 다음 다음 동작을 재생한다.
5. 모든 동작을 재생한 뒤 같은 순서를 다시 시작한다.
6. 걷기 또는 달리기 동작 중 왼쪽/오른쪽 방향키로 수동 이동할 수 있고, 지정된 동작은 자동으로 왼쪽에서 오른쪽으로 이동한다.
7. 사용자가 창 닫기 이벤트를 보내면 프로그램이 정상 종료된다.

## 5. 기능 요구사항

| ID | 요구사항 | 완료 기준 |
|---|---|---|
| FR-01 | 시작 및 자산 로드 | 프로그램 실행 시 `sonic-sprite.png`를 불러와 뷰어 창을 표시한다. 이미지가 없거나 로드할 수 없으면 원인을 알 수 있는 오류를 출력하고 비정상적인 이미지 접근 없이 종료한다. |
| FR-02 | 동작 및 프레임 구성 | 스프라이트 시트에서 각 프레임의 실제 경계를 개별 확인해 목록화하고, 식별 가능한 모든 동작을 재생 대상으로 포함한다. 한 프레임의 crop에 이웃 프레임이 포함되지 않아야 한다. |
| FR-03 | 프레임 애니메이션 | 현재 동작의 프레임을 정해진 순서로 시간에 따라 표시한다. 프레임 인덱스는 동작의 프레임 수를 넘지 않고 끝에서 처음으로 순환한다. |
| FR-04 | 화면 표시 | 1400×700 캔버스에서 스프라이트를 원본 비율로 확대하고, 모든 프레임의 발 기준선을 맞춘다. 프레임 일부나 이웃 이미지가 잘려 보이지 않아야 한다. |
| FR-05 | 동작 반복 | 각 동작의 프레임 애니메이션을 정확히 5회 재생한 후 다음 동작으로 이동한다. |
| FR-06 | 동작 간 대기 | 동작을 5회 재생한 뒤 다음 동작을 시작하기 전 1초간 대기한다. 마지막 동작 뒤에도 동일하게 대기한 다음 처음 동작으로 돌아간다. |
| FR-07 | 전체 순서 반복 | 스프라이트 시트에서 정한 동작 순서를 끝까지 재생한 다음, 첫 동작부터 같은 순서로 무한 반복한다. |
| FR-08 | 종료 처리 | 창 닫기 이벤트를 처리하고 pico2d 리소스와 프로그램을 정상적으로 종료한다. |
| FR-09 | 수동 이동 | 걷기/달리기 동작 중 방향키를 누르고 있으면 초당 240픽셀 기준으로 이동한다. 키를 놓거나 전환 대기 중에는 수동 이동을 멈추고, 반대 방향 동시 입력은 상쇄한다. |
| FR-10 | 자동 이동 동작 | 시트 2행(달리기), 4~5행 결합 동작, 6행, 7행은 한 동작의 5회 반복 재생 전체에 걸쳐 왼쪽 경계에서 오른쪽 경계까지 자동 이동한다. 프레임 속도와 무관하게 시작/끝 위치가 일정해야 한다. |
| FR-11 | 이동 경계 및 방향 | 스프라이트가 창 밖으로 나가지 않도록 좌우 위치를 제한한다. 왼쪽으로 수동 이동할 때는 수평 반전하고, 오른쪽 이동 시 원래 방향으로 표시한다. 비이동 동작과 전환 대기 중에는 수동 입력으로 위치가 바뀌지 않는다. |

## 6. 비기능 요구사항 및 제약

- 애니메이션과 대기 시간은 프레임 카운트가 아니라 경과 시간을 기준으로 처리한다. 실행 환경의 프레임 속도 변화가 1초 대기 및 동작 반복 횟수를 바꾸지 않아야 한다.
- 이동 위치도 경과 시간 기준으로 갱신해 프레임 속도에 따라 이동 속도가 달라지지 않게 한다.
- 자동 이동은 프레임 수와 5회 반복 진행률로 위치를 계산해 업데이트 간격에 관계없이 각 동작의 전체 이동 거리를 유지한다.
- 캔버스는 1400×700 픽셀로 구성하고, 프레임별 실제 불투명 경계를 사용해 이웃 스프라이트가 crop에 섞이지 않게 한다.
- 확대 시 가로세로 비율을 유지하고, 스프라이트가 창을 벗어나 잘리지 않도록 한다.
- 애플리케이션 구현은 `sonic_animation_viewer.py` 한 파일에 둔다. 입력 스프라이트 시트는 제공된 별도 이미지 파일로 유지한다.
- 코드와 실행은 저장소에서 사용하는 Python 및 pico2d 환경을 전제로 한다.
- 정확한 프레임 경계, 동작별 프레임 수, 동작 순서는 이미지 자산을 기준으로 확인해 구현 단계에서 기록한다. 이 문서에서 추정값을 고정하지 않는다.

### 제공 스프라이트 자산 기록

- `sonic-sprite.png`는 399×525 픽셀의 PNG이며, 8비트 RGBA 색상과 알파 채널을 사용한다.
- 이미지에는 투명 배경이 포함되어 있어 뷰어 배경색 위에 스프라이트를 표시할 수 있다.

### 애니메이션 스트립 목록

스프라이트 간격은 일정한 40픽셀 격자가 아니다. 각 프레임을 알파 채널의 실제 픽셀 경계로 개별 정의하고, 좌표는 이미지 왼쪽 위 기준으로 저장한다. 4~5행은 하나의 동작으로 연결하고, 8행과 마지막 행은 지정된 프레임 수에서 나눈다. 제목과 하단 크레딧은 재생 대상에서 제외한다.

| 동작 | 스프라이트 시트 영역 | 프레임 수 | 이동 방식 |
|---:|---|---:|---|
| 1 | 1행, 걷기 | 11 | 방향키 수동 |
| 2 | 2행, 달리기 | 12 | 좌→우 자동 및 방향키 |
| 3 | 3행 | 6 | 제자리 |
| 4 | 4~5행 결합 | 15 | 좌→우 자동 |
| 5 | 6행 | 6 | 좌→우 자동 |
| 6 | 7행 | 6 | 좌→우 자동 |
| 7 | 8행 앞 6프레임 | 6 | 제자리 |
| 8 | 8행 뒤 2프레임 | 2 | 제자리 |
| 9 | 9행 | 8 | 제자리 |
| 10 | 마지막 행 앞 2프레임 | 2 | 제자리 |
| 11 | 마지막 행 뒤 2프레임 | 2 | 제자리 |

재생 대상은 총 11개 동작, 76프레임이다.

## 7. 검수 기준

1. `Labs/LEC09`에서 프로그램을 실행하면 제공된 이미지가 표시된다.
2. 1400×700 캔버스에서 스프라이트가 원본 비율을 유지하고 발 기준선이 고정된다.
3. 확인된 모든 동작이 정해진 순서대로 재생된다.
4. 각 동작은 정확히 5회 재생되고, 다음 동작 전 대기 시간은 1초다.
5. 마지막 동작 다음에는 1초 대기 후 첫 동작부터 전체 순서가 다시 시작된다.
6. 창을 닫으면 프로그램이 정상 종료된다.
7. 이미지 파일이 없는 경우 오류가 명확하게 드러나며 traceback에 의존하는 불명확한 종료를 하지 않는다.
8. 걷기/달리기 동작 중 방향키를 누르고 있는 동안 연속 이동하고, 키를 놓으면 멈추며, 화면 가장자리에서 캐릭터가 잘리지 않는다.
9. 걷기/달리기 이외의 동작에서는 방향키를 눌러도 위치가 바뀌지 않는다.
10. 각 프레임은 자체 경계로 잘려 이웃 프레임의 픽셀이 섞이거나 캐릭터 일부가 잘리지 않는다.
11. 동작 사이 1초 대기 중에는 방향키를 누르고 있어도 위치가 바뀌지 않는다.
12. 2행, 4~5행 결합, 6행, 7행 동작이 왼쪽 경계에서 오른쪽 경계까지 자동 이동하고, 프레임 갱신 간격을 바꿔도 끝 위치가 같다.

## 9. 완료 정의

- FR-01부터 FR-11까지의 완료 기준을 만족한다.
- 검수 기준의 모든 항목을 수동 실행으로 확인한다.
- 단일 파일 제약을 지키며, 외부 입력 이미지가 지정된 위치에서 로드된다.
- 단계별 검증 결과를 기록하고, 모든 변경을 최종 단일 커밋으로 반영한다.

### 23단계 검증 기록

- 알파 경계 분석으로 확인한 76개 프레임의 실제 사각형과 코드 매핑이 모두 일치함을 확인했다.
- 이미지 파일 누락 시 오류를 출력하고 창을 열지 않는 동작을 확인했다.
- 합성 `SDL_QUIT` 이벤트로 렌더 루프 종료 및 창 정리 경로를 확인했다.
- 전체 순환을 큰 시간 간격으로 한 번 갱신한 결과와 0.05초 간격으로 나눈 결과가 일치함을 확인했다.

### 30단계 이동 검증 기록

- 방향키 `KEYDOWN`/`KEYUP`, 키 해제 후 정지, 좌우 동시 입력 상쇄를 확인했다.
- 걷기/달리기에서만 초당 240픽셀로 이동하며 좌향 반전이 적용됨을 확인했다.
- 좌우 경계에서 잘리지 않고, 다른 동작에서는 위치가 유지됨을 확인했다.
- 0.5초 한 번 갱신과 0.05초 열 번 갱신의 이동 결과가 일치함을 확인했다.

### 35단계 프레임 및 이동 최종 검증 기록

- 76개 개별 crop이 투명 픽셀로 검출한 각 프레임 경계와 정확히 일치한다.
- 1400×700 창에서 13배 확대와 공통 발 기준선을 유지하며 전체 프레임이 화면 안에 표시된다.
- 실제 렌더 루프에서 오른쪽 0.5초 이동 후 X=820, 키 해제 후 정지, 왼쪽 0.25초 이동 후 X=760 및 수평 반전을 확인했다.
- 걷기/달리기 동작의 1초 전환 대기 중에는 이동 입력이 위치를 바꾸지 않음을 확인했다.

### 38단계 그룹 및 자동 이동 검증 기록

- 재생 그룹 프레임 수는 11, 12, 6, 15, 6, 6, 6, 2, 8, 2, 2이며 총 76프레임이다.
- 4~5행 결합, 8행 6+2 분할, 마지막 행 2+2 분할에서 프레임 누락이나 중복이 없다.
- 실제 PNG/pico2d 렌더에서 달리기, 4~5행 결합, 6행, 7행이 X=260에서 시작해 480, 700, 920을 거쳐 X=1140까지 이동한다.
- 자동 이동 위치가 5회 재생 진행률을 따르며, 동작 전환 대기 중에는 끝 위치를 유지한다.
- 최종 검증 후 모든 변경을 한 번의 커밋으로 기록한다.

## 10. 실행 방법 및 자산 가정

`Labs/LEC09` 폴더에서 아래 명령으로 실행한다.

```powershell
python sonic_animation_viewer.py
```

실행 환경에는 Python과 `pico2d`가 설치되어 있어야 하며, `sonic-sprite.png`는 Python 파일과 같은 폴더에 둔다. 뷰어 캔버스는 1400×700 픽셀이다. 걷기/달리기 동작 중 왼쪽/오른쪽 방향키를 누르고 있으면 이동하며 키를 놓으면 멈춘다. 창을 닫으면 프로그램이 종료된다.

현재 구현은 제공된 399×525 스프라이트 시트의 실제 알파 경계로 정의한 11개 동작 그룹과 76개 개별 crop 사각형을 사용한다. 4~5행은 결합하고, 8행은 6+2, 마지막 행은 2+2 프레임으로 나눈다. 달리기 및 4~5행 결합, 6행, 7행 동작은 재생 중 좌→우 이동한다. 걷기/달리기는 방향키 수동 이동도 지원한다. 시트 이미지나 프레임 배치가 바뀌면 프레임 매핑을 다시 확인해야 한다. 프레임 표시 간격은 0.1초이며, 각 동작을 5회 재생하고 1초 대기한 뒤 다음 동작으로 이동한다. 수동 이동 속도 기본값은 초당 240픽셀이다.
